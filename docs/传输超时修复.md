# 首次预测超时：现场诊断与修复

2026-11-04失败录制`20261104_203854_fold_towel`在开始后约1秒退出，policy_steps=0。服务进程是在两条JAX调用签名预热修复后启动的，因此不能继续将这次问题归因于旧进程或漏预热。

只读该录制的第一对图像，经实验室—Windows—训练服务器两条SSH链路重放：原始JPEG共95431字节，旧客户端的PNG请求变成724988字节；三次往返约1.821、1.008、0.876秒。诊断使用10秒接收上限，只记录并丢弃模型输出，不执行动作。这个诊断时限从未应用到机器人客户端。

新版客户端直接发送训练预处理那一次JPEG-q90编码产生的原始字节。服务端解码得到的RGB与原客户端PNG路径逐像素相同；没有新增有损压缩，也没有resize、颜色、动作顺序或归一化变化。已解码保存观测的数值对照仍用PNG。

更新后的实验室录制重放，JPEG请求为95470字节，五次往返约0.598、0.344、0.374、0.420、0.375秒。相对旧PNG，数据量下降约86.8%。这次是通过临时Paramiko双SSH转发测试，路径经过同一台Windows和两台服务器，但实现与用户手工OpenSSH窗口不同，常用隧道仍需重新验证。

原validate.sh只测固定噪声PNG回放，未覆盖正常请求。新版分为两个必须都通过的阶段：

- 只比较保存参考值的数值回放：单独10秒接收上限，输出只作数值比较，不进入伺服；最大允许差0.002。
- 实时链路：五次正常noise=None、JPEG训练预处理请求，原RemotePolicy客户端、原1秒预测时限。任一次失败都不生成通过凭证。

现场新版自检实际通过：数值回放最大误差0.0009764，正常五次请求约0.361、0.490、0.428、0.482、0.429秒。见原始JSON报告。没有提高机器人预测时限或动作截止时间。

测试：本地18项回归通过；服务器第一版传输更新17项通过；实验室最终客户端13项通过。测试验证JPEG字节复用、像素等价、夹爪约束、错误模型、断连、过期响应、空闲等待和数值回放/实时限时分离。不是全部训练环境或实机任务重新验收。
